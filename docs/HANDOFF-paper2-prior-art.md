# 交接：第二篇论文方向的前人工作调研

给接手做文献/产品调研的人或模型。**目的是找出已经有人做过的东西。找到了是好消息，不算失败。**

## 一、背景：第一篇做了什么

已发布：*What Context Compression Cannot Buy: Diagnosing the Recall Ceiling with a
Frozen Backbone*（Zenodo DOI 10.5281/zenodo.22897854）

做法：把长对话的 KV cache 压成"64 个学出来的记忆槽 + 按需调回的 512 条原文 KV"，
主干模型完全冻结，只训练记忆槽。主要结论：

- 压缩的上限由"答案能不能从上下文里直接复制"决定。可以推断的内容能压缩，
  精确的字符串（名字、数字）压不了
- **选择是瓶颈**：同样 512 条预算，oracle（知道答案时的最优选择）能恢复 98%，
  现有的注意力打分只有 75%（自然文本）；在 needle 任务上是 98% 对 5%
- 在 needle 类任务上排序翻转：我们的方法输给了 SnapKV 和 StreamingLLM
- 从 0.6B 到 14B，检索和压缩各自不随规模变化，两者组合呈倒 U 形

## 二、第二篇的候选方向

**A. 学出来的检索器**：用 oracle 的选择当监督信号，训练一个轻量模块预测
"该调回哪些 KV 条目"，替代注意力打分。直觉是：抽象状态存不下具体字符串，
但可以学会记住"东西放在哪"，相当于一个学出来的索引。

**B. 按场景自适应检索**：先判断当前请求属于"价值弥散"（续写、闲聊）
还是"价值集中"（问某个具体事实），再切换检索方式：分散的 token 还是连续的段；
用生成的草稿当查询，还是用用户原话当查询。

**C. 落地**：本地 AI 伴侣（消费级 8GB 显卡）的长期对话记忆，在 KV 层面做，
而不是文本 RAG。目标模型是 Qwen3.6-35B-A3B（MoE）。

## 三、需要回答的问题（按优先级）

**Q1（最重要）**：有没有人训练过**专门的 KV 检索/选择器**，监督信号来自
oracle、未来的注意力、或下游 loss？

已知的近邻（不用再查，但请说明你找到的是否比它们更接近 A）：
- Self-Pruned KV Attention，arXiv 2605.14037：学一个效用预测器决定是否写入缓存，主干一起训练
- SpeCache，arXiv 2503.16163：预测下一步要看哪些 KV 并提前取回，但不是学出来的
- Quest 2406.10774、InfLLM 2402.04617：按块打分检索，不训练

请重点区分：(1) 学的是"写入/驱逐"还是"调回/检索"；(2) 主干冻结还是一起训；
(3) 监督信号是什么。

**Q2**：有没有**按任务类型或查询类型切换压缩/检索策略**的工作？
例如识别出当前是问答就换一种策略。

**Q3（落地）**：有没有**已经部署**的系统，把 KV 级记忆（不是文本摘要或向量库）
用在长期对话、陪伴或个人助理产品里？
- 开源项目和产品都算，不只是论文
- MemGPT/Letta、MemoryBank、mem0 这类是**文本层**记忆，不算；
  但如果有论文直接比较过 KV 层和文本层，请列出
- KV cache 跨会话持久化或复用的系统（LMCache、CacheBlend 这一类）也请列出，
  并说明它们有没有做压缩或选择

**Q4**：有没有在 **MoE 模型**（Qwen3-MoE、Mixtral、DeepSeek-MoE 等）上做
KV 压缩或记忆 token 的工作？有没有发现 MoE 和稠密模型表现不一样？

## 五、注意事项

1. **排除我们自己的东西**：github.com/HoshiGT/frozen-kv-memory 和
   Zenodo 记录 10.5281/zenodo.22897854 都会被搜到，它们不算前人工作
2. **必须给 arXiv ID 或可验证的链接**，不确定就标"存疑"。
   **不要编造论文，也不要根据主题猜标题**。上次核验时发现过这种情况：
   ID 能对上，标题却是论文正文里的一句话
3. **找到前人工作是好消息**。目的是弄清还剩多少空间，不是证明我们有新意。
   如果 A 已经有人做完了，直接说
4. 时间范围 2023–2026，2026 年的新工作尤其重要，这个领域变化很快
5. "落地"指真的有人在用：产品、开源项目、部署报告。
   论文里写一句"可以用于..."不算
